# ADR-0001：监控轨与研究轨双轨架构

- 状态：已接受（仅批准研究轨开发阶段0技术 Spike；ECS部署验证阶段0需独立验收）
- 日期：2026-08-11
- 决策人：项目审批方
- 关联计划：[智能信源采集与分析落地执行计划](../../智能信源采集与分析落地执行计划.md) v1.2

> 术语统一：研究轨开发阶段0指本地代码与测试基线；ECS部署验证阶段0指 ECS 旁路部署、真实任务、容量和 48 小时验证。

## 背景

现有平台擅长把固定、受控信源转换为可追溯风险信号，经一次 AI 解析、事件归并、确定性供应商匹配和本地规则评分形成 P1-P4 风险提醒。继续让专用数据源接入助手覆盖动态网页、反爬和任意站点，会显著增加适配成本、安全面和运维复杂度，仍无法自然支持行业趋势、原材料价格和专题研究。

新的产品诉求是从不限于预设信源的公开信息中搜索、读取和交叉验证材料，形成带逐条引用的内部研究报告。该报告仅供管理层及相关业务人员参考，不作为重大决策核心依据，也不能绕过现有确定性评分链。

## 可选方案

### 方案 A：继续扩展专用数据源接入助手

优点是复用既有声明式适配器、调度和风险处理链。缺点是动态网页和站点差异会导致长期逐源开发；写入型工具与通用浏览工具混合后，权限、SSRF、WAF 和误采集风险扩大；所有内容进入风险链也会混淆研究材料与正式风险事实。

### 方案 B：所有网络信息直接进入现有监控轨

优点是数据模型和页面改动较少。缺点是研究性、预测性内容会被迫事件化和 P 分级，难以表达事实、推断、预测及其不确定性，并可能把未经确认的模型结论误作正式风险依据。

### 方案 C：监控轨与研究轨隔离

监控轨保留固定信源、一次 AI 解析、确定性匹配和本地评分；研究轨以独立异步任务执行搜索、单页读取、来源分级、交叉验证和逐条引用报告。只有管理员人工确认的单条研究结论可以幂等转为风险信号。

## 决策

采用方案 C。

```text
监控轨：固定信源 → 风险信号 → 一次 AI 解析 → 风险事件 → 匹配 → 本地评分 → P1-P4

研究轨：研究任务 → 搜索 → 单页读取 → 来源分级/交叉验证 → 结论+引用 → 研究报告
                                                        │
                                  管理员确认单条结论 ────┘ → 风险信号
```

具体约束：

1. 未人工确认的研究结论永不进入评分链；研究报告不自动获得 P1-P4 等级。
2. 只有 `risk_admin` 和 `platform_admin` 可以将单条结论转为风险信号，且按研究结论保持幂等和完整审计。
3. 长研究任务由独立 `research-worker` 异步执行；FastAPI 只创建任务、查询状态和执行人工确认，Scheduler 只创建到期任务。
4. 研究轨开发阶段0和 ECS部署验证阶段0的 Crawl4AI 仅允许受限单页读取，不开放任意深爬、浏览器点击、登录、验证码或反爬绕过。
5. 旁路组件发出请求前，平台必须对最终目标域名取得租约；旁路返回最终 URL、重定向链和 HTTP 状态，逐跳执行地址校验、限速、冷却和熔断。
6. n8n 不进入当前阶段；只有真实流程复杂度证明现有 Scheduler 与 Worker 不足时再评估。
7. 研究查询遵循数据最小化；任务、来源、引用、报告和工具日志使用独立留存策略与预算上限。

## 结果与代价

正向结果：

- 保持正式风险提醒的确定性、可解释性和既有证据边界。
- 允许平台扩展到供应商风险之外的行业趋势、政策、原材料和供应链专题研究。
- 通用读取工具与数据源发布/启用工具隔离，降低越权写入和误采集风险。
- 研究结论可以在人工闸门后复用现有监控链，无需建设第二套评分体系。

代价与责任：

- 需要新增异步任务、来源、引用、结论和报告模型，以及 Worker 运行与恢复机制。
- RSSHub/Crawl4AI 旁路治理不能自动复用现有请求控制，必须实现明确契约。
- 2 核 4G 仅能作为低并发验证环境；长期共存可能需要 4 核 8G 或拆分实例。
- 带引用不等于结论必然正确，仍需来源分级、交叉验证、事实/推断/预测区分和人工使用边界。

## 研究轨开发阶段0与 ECS部署验证阶段0开工门

研究轨开发阶段0开始前必须完成代码和测试范围确认；ECS部署验证阶段0开始前还必须同时完成：

1. 选定 2 个试点固定信源、1 个公开研究主题及其公开访问边界。
2. 固定 RSSHub、Crawl4AI 和应用镜像版本，准备 SBOM 与高危/严重漏洞扫描结果。
3. 确定搜索 Provider 实测方案、查询最小化规则、单任务与全局 Token/金额上限及止损方式。
4. 书面确认旁路最终域名租约、重定向逐跳校验和返回审计字段的执行契约。
5. 明确 48 小时浸泡指标：零 OOM、零重复任务、零未处理积压，整机峰值后保留 25%～30% 资源余量。

研究轨开发阶段0和 ECS部署验证阶段0只产生可行性、容量、安全和成本证据，不授权正式发布或自动研究。阶段 1 和阶段 2 必须分别重新审批。
