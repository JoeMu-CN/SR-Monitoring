# Google AI Studio 提示词：研究 Agent 与 LangGraph 动态执行图

> 用途：交给 Google AI Studio 生成或重构“研究轨”前端页面。
> 目标：保持项目现有 Google AI Studio 版本的全部视觉语言，在不改变现有接口语义的前提下，升级为可展示 LangGraph 受控研究流程的高密度企业控制台。

## 可直接复制的提示词

```text
请为“供应商风险监控平台”设计并实现一个高保真的“研究 Agent”前端页面。它是现有研究轨页面的升级，不是新建营销页，也不是独立的科技大屏。

一、产品背景与真实性边界

平台有两条互相隔离但可受控融合的链路：

1. 监控轨：自动采集公开风险信息，经确定性供应商匹配和规则评分形成 P1-P4 风险提醒。
2. 研究轨：围绕供应商、企业、行业、政策、原材料和供应链主题，生成带逐条引用的研究报告草稿。

研究 Agent 使用 LangGraph 做受控流程编排，但平台数据库仍是任务、租约、预算、证据、引用、报告和审计的唯一业务事实来源。界面不得模拟或展示模型隐藏思维链，不得用预设动画冒充真实执行过程。

研究报告只能标记为“草稿 · 待人工确认”“AI 生成，仅供参考”，不得自动发布、不得自动进入 raw_signals、不得改变 P1-P4，也不得设计库存分析、替代供应商推荐、风险处置工单或自动决策功能。

二、技术栈与实现要求

- React 19 + TypeScript。
- Tailwind CSS 4。
- Lucide React 图标。
- Motion 用于状态过渡、节点高亮、连线流动和面板展开。
- 不引入新的图形库；桌面端用 DOM 节点实际位置计算 SVG 贝塞尔连线。
- 保留现有 API、权限、显式“开始研究”、取消任务、任务列表、供应商范围选择、来源列表和报告草稿交互。
- 事件通过现有增量接口轮询：GET /api/v1/research/tasks/{task_id}/events?after_id=0&limit=200。
- 轮询频率约 2.5 秒；只追加新事件，不重放整页动画。
- 设计稿可以使用明确标注为“演示数据”的示例状态；生产代码只能根据真实 API 事件更新节点。

三、核心页面目标

让风险分析员在一个页面内回答四个问题：

1. 当前研究任务执行到哪一步？
2. 系统刚刚调用了哪个受控工具，结果是什么？
3. 为什么发生补充搜索、阻断、冷却、跳过或证据不足？
4. 当前使用了多少步骤、搜索、页面、Token 和预算，还能否继续？

页面模式是 Operate：优先保证扫描效率、状态清楚、证据可追溯和操作安全。整体专业、可信、克制，信息密度高但层级明确。

四、桌面端页面结构（1440px 基准）

沿用现有 App Shell：240px 左侧主导航、粘性顶栏、最大 1440px 内容区。研究 Agent 页面内部采用三栏工作区：

1. 左栏 280-300px：研究任务和新建任务。
2. 中栏 minmax(0, 1fr)：受控研究执行图，是页面视觉与操作中心。
3. 右栏 300-340px：选中节点详情、工具结果、治理状态和事件日志。

顶栏：

- 左侧只显示蓝色“供应商风险监控平台”。
- 页面上下文显示“研究 Agent · 执行中”。
- 显示紧凑、真实的预算摘要：步骤 7/12、搜索 2/3、页面 4/5、Token 32,540/120,000。
- 右侧提供“暂停/继续”（仅在后端支持时显示）和“取消任务”。现有后端不支持的操作不要做成可点击按钮。

左侧任务栏：

- 标题“研究任务”，主按钮“新建任务”。
- 任务项展示研究主题、任务 ID、创建时间、任务类型和状态。
- 状态至少覆盖：等待开始、等待 Worker、执行中、已完成、失败、已取消。
- 当前任务使用系统蓝描边和浅蓝底，不使用重阴影。
- 新建任务区域保留研究主题输入、供应商搜索多选、范围安全提示和“创建任务”。
- 未选择供应商时明确提示：“未选择时不会读取全库监控信号”。
- 创建后仍需用户点击“开始研究”，不得自动触发外部搜索或模型调用。

中间执行图：

- 标题“受控研究执行图”。
- 顶部图例区分：监控轨证据、公网检索、Agent 判断、已完成、执行中、失败/阻断、跳过/冷却。
- 提供缩放、适应视图、锁定画布、减少动效控件。
- 使用从左到右、分层布局的有向流程图，不使用随机力导向图、知识图谱气泡或无规则漂浮节点。
- 流程图下方放置“事件时间线”，显示只追加事件 ID、时间、状态和短标签。
- 显示固定真实性提示：“仅展示后端已记录事件”。

右侧节点详情：

- 点击节点后显示节点名称、状态、父节点、开始时间、结束时间或持续时长。
- 显示脱敏输入/输出统计、来源或引用内部 ID、失败分类和下一动作。
- 不显示搜索密钥、模型请求体、完整网页正文、Cookie、异常堆栈、任意浏览器参数或完整 URL。
- 工具调用以可折叠行展示：工具名、受控参数摘要、状态、耗时、结果计数。
- 单独设置“治理与安全控制”区，显示预算门禁、取消检查、工具白名单、来源冷却和“隐藏思维链：不记录”。

五、LangGraph 节点与条件边

执行图需要能够承载以下规划节点。设计稿可以展示一次正在运行的完整示例；生产实现必须根据后端返回的 node_key、parent_node_key 和 status 动态创建或更新节点。

主流程：

initialize
→ load_supplier_context
→ load_monitoring_evidence
→ plan_queries
→ search_web
→ rank_candidates
→ read_candidate

候选读取分支：

- 静态正文成功 → register_evidence
- 空正文或需要 JavaScript → read_with_crawl4ai → register_evidence
- 已登记 RSSHub 路由 → read_registered_feed → register_evidence
- 403 / WAF / robots / 认证要求 → block_source
- 429 → cool_down_source

证据判断与循环：

register_evidence
→ evaluate_evidence

- 证据不足且预算允许 → refine_queries → search_web，形成清晰可见的条件循环边。
- 证据充分 → compose_report。
- 达到步骤、搜索、页面、Token 或金额上限 → compose_insufficient_report。

报告与回验：

compose_report
→ verify_claim_citations

- 引用回验失败 → remove_or_downgrade_claim → verify_claim_citations。
- 引用回验通过 → persist_report → finish。

六、节点卡片内容

每个节点不是大卡片，而是紧凑的流程块，默认宽约 148-180px。必须包含：

- Lucide 线性图标。
- 中文短名称；必要时在详情中显示稳定 node_key。
- 状态文字和非颜色状态图标。
- 运行中显示持续时间；完成后显示最终耗时。
- 与节点相关的一个关键计数，例如候选 6、已读 4、引用 9、缺口 2。
- 失败或跳过时显示脱敏分类，不直接显示原始异常。

状态视觉：

- pending：灰色描边，低对比，虚线入边。
- running：系统蓝描边、2px 可见焦点环、微弱呼吸指示；不得整卡发光。
- succeeded：绿色状态点或勾，保持原节点类型颜色。
- failed / blocked：红色状态图标和描边。
- skipped / cooldown：灰色或橙灰色，显示跳过/冷却原因。
- info：中性蓝，仅表达事件信息，不伪装为成功。

节点类型颜色：

- 监控轨证据：#ff9500，仅表达监控轨来源，不代表风险等级。
- 公网搜索、候选、受控读取：#007aff。
- Agent 规划、排序、评估：青蓝或中性蓝，但仍属于现有蓝色体系。
- 已登记证据、引用回验、草稿持久化：#34c759。
- 阻断与失败：#ff3b30。
- 跳过与域名冷却：#8e8e93。

七、连线与动态效果

- 连线使用 1-1.5px SVG 贝塞尔曲线和小箭头，避免粗管线。
- 已完成路径为稳定实线；等待路径为低对比虚线；失败路径为红色短段。
- 当前正在运行的边允许一个小型蓝色光点沿路径移动，持续 1.2-1.8 秒，禁止粒子雨和持续闪烁。
- 新事件到达时，对对应节点做 180-240ms 的淡入/轻微上移，并将旧状态平滑过渡为新状态。
- 条件循环边要有短标签，例如“证据不足 · 预算允许”；标签可点击并打开该判断事件详情。
- 点击节点后保持选中焦点；按 Escape 清除选中；支持方向键在相邻节点间移动。
- prefers-reduced-motion 下关闭路径移动与呼吸动画，只保留即时颜色、图标和文本状态变化。
- 动画不能延迟真实任务状态更新，也不能成为理解流程的必要条件。

八、监控证据与公网证据融合

- “载入监控轨证据”只展示任务显式 supplier_scope 范围内的当前、已完成成功分析且 needs_review=false 的公开 HTTPS 信号快照。
- 监控轨证据与本次 web_search 来源进入同一个证据池，但来源类型必须持续可辨。
- 来源按 URL、正文哈希和信号指纹去重；重复来源保留 skipped 事件，便于回放。
- 无 supplier_scope 时显示 monitoring_context_skipped，文案为“未指定供应商范围，未读取监控轨证据”，不得回退读取全库。
- 待复核信号不得表现为已确认事实。

九、右侧详情的推荐示例

选中节点：评估证据
状态：执行中
父节点：登记证据
开始时间：00:03:28
已运行：00:00:18
证据条目：12
引用回验通过：9
低置信度：1
来源阻断：2
当前证据缺口：2 项
下一动作：预算允许时补充查询

治理与安全控制：

- 预算门禁：允许 1 次补充搜索
- 取消检查：通过
- 工具白名单：通过
- 隐藏思维链：不记录

以上均为设计稿演示数据；正式页面必须来自任务与事件 API，不得硬编码为真实统计。

十、视觉系统

必须延续项目现有 Google AI Studio / macOS Sonoma 风格，不建立第二套设计系统。

颜色：

- 主色：#007aff；悬停：#0062cc。
- 浅色画布：#f1f5f9；表面：#ffffff；主文字：#101d28。
- 深色画布：#0b131e；深色抬升面：#0e1726。
- P1：#ff3b30；P2：#ff9500；P3：#007aff；P4：#8e8e93。
- 成功：#34c759。

字体：

- 中文：Noto Sans SC、Microsoft YaHei、sans-serif。
- ID、时间、Token、预算：IBM Plex Mono、ui-monospace、monospace。
- 页面标题 24px / 900；区块标题 14-18px / 700；正文 13-14px；标签 11-12px。

组件：

- 标准圆角 12px，重点面板 16px，紧凑控件 8px。
- 静态表面以 1px 描边和明度差分层，阴影极轻。
- 不使用泛滥卡片网格；执行图应是一块连续画布。
- 使用 Lucide 图标，不使用 emoji。
- 所有键盘焦点具有 2px 系统蓝焦点环。

禁止：

- 紫色霓虹、赛博朋克、装饰性渐变、玻璃拟态、渐变文字、粒子背景。
- 营销页 Hero、大号口号、虚构 KPI、假在线状态、假用户头像。
- 把每个内容都做成同尺寸卡片。
- 用动态气泡或思维导图暗示模型隐藏推理。
- 为研究草稿附加 P1-P4，或提供自动发布/自动处置按钮。

十一、响应式

- ≥1280px：三栏完整布局，右侧节点详情常驻。
- 1024-1279px：左侧任务栏可折叠，右侧详情变为抽屉；中央图保持可缩放。
- 768-1023px：隐藏桌面主侧栏，使用项目既有底部主导航；任务列表变为顶部选择器；节点详情使用底部抽屉。
- <768px：不强塞网络图，切换为相同真实事件数据的纵向时间线；每项显示父子层级、状态、时间和可展开详情。
- 最低支持 320px；主要触控目标不小于 44px；页面底部预留固定导航安全区。

十二、必须设计的状态

- 没有研究任务。
- 已创建但尚未点击“开始研究”。
- 已请求执行，等待 Worker。
- 正常执行并收到增量事件。
- 预算不足或达到硬上限，生成证据不足报告。
- 来源被 403/WAF/robots 阻断。
- 429 域名冷却。
- 用户取消中和已取消。
- Worker 失败，但已发生事件仍可回放。
- 任务完成，报告草稿待人工确认。
- 事件接口加载失败，可重试但不清空已有事件。
- 无障碍减少动效模式。

十三、交付要求

请输出：

1. 完整桌面端页面实现。
2. 窄屏时间线实现。
3. 可复用组件：ResearchAgentWorkspace、ResearchGraphCanvas、ResearchGraphNode、ResearchGraphEdge、ResearchNodeInspector、ResearchEventTimeline、ResearchBudgetBar。
4. 清晰的 TypeScript 类型，直接兼容 task、event、source、report 数据。
5. 使用演示数据时集中放在单独 mock 文件，并明确标注“仅用于 UI 预览”，便于后续替换成现有 API。
6. 不修改后端接口，不引入新的业务能力，不使用新图形依赖。
```
