# 受控研究 Agent、全供应商月报与可选周报实施方案

**文档状态**：后端分阶段实施中；未部署 ECS
**规划日期**：2026-08-16
**适用范围**：本地研究轨；不代表已部署 ECS，不授权真实搜索、网页读取或模型调用
**实施顺序**：文档确认 → 后端 Spike → 后端正式实现 → 后端验收 → 前端适配 → 本地镜像验收 → 另行评估 ECS

## 1. 背景与纠偏目标

当前 `topic_source_discovery` 的真实执行路径是“单次主题搜索 → 固定循环读取候选 → 单次报告生成”。它已经具备任务租约、预算、受控 HTTPS、监控信号融合、引用回验和执行事件，但不具备自主查询规划、工具选择、证据缺口判断、补充搜索和失败恢复，因此不能等同于研究 Agent。

现有定期研究调度还有一个关键语义缺口：Scheduler 创建的日报/周报任务使用空 `supplier_scope`，而研究轨约定空范围不得读取全库监控信号。仅增加一个月报 cron 无法实现“对全部供应商执行定期风险研究”。

本方案同时纠正两项能力：

1. 使用 LangGraph 把研究轨升级为步骤受限、状态可恢复、工具可审计的受控研究 Agent。
2. 月报默认只对最多 100 家启用供应商逐一创建研究任务，并使用与手动研究相同的 Agent 图执行；保留显式全量开关，额度和预算增加后可覆盖全部启用供应商。周报复用完全相同的批次流程和研究图，但以资金与容量门禁后的手动开关控制，默认关闭。

## 2. 关键取舍

### 2.1 框架取舍

| 方案 | 优点 | 代价与风险 | 决策 |
|---|---|---|---|
| 完全自研循环 | 依赖少、边界清晰 | 自行处理图分支、检查点、暂停恢复，容易重复造轮子 | 不采用 |
| LangGraph 编排 + 现有 Provider/Pydantic | 最小迁移，能复用现有任务与安全治理 | 需要编写少量节点适配器 | **采用** |
| 直接集成完整通用 Agent 框架 | 可快速获得通用工具循环 | 与现有任务、预算、安全、引用和审计体系重复 | 不采用 |

技术方案确定为 LangGraph 作为唯一流程编排器，继续使用现有 `AIProvider` 完成模型调用，使用原生 Pydantic 模型校验规划动作、证据评估和报告输出。工具执行、预算扣减、错误分类、Token统计、引用回验和审计继续由平台控制，不再引入第二套模型或 Agent 运行时。

### 2.2 全供应商调度粒度取舍

| 方案 | 问题 | 决策 |
|---|---|---|
| 一个任务包含全部供应商 | 供应商间证据混杂；单点失败影响整批；预算、重试、报告难隔离；现有监控证据上限会跨供应商竞争 | 不采用 |
| 每个供应商独立建立一套 cron | 调度项数量随供应商增长，变更和幂等管理复杂 | 不采用 |
| 一个周期批次，批次内每供应商一个子任务 | 调度入口固定；任务隔离；可串行削峰；易做部分成功和组合报告 | **采用** |

月报的默认范围定义为：调度触发瞬间按 `Supplier.id` 升序排列的启用供应商前 `RESEARCH_MONTHLY_SUPPLIER_LIMIT` 家，默认上限为 100 家。该切片不增加“核心供应商”字段，100 家试点范围通过配置和稳定排序确定；范围外供应商继续保留在监控轨，但不进入月报批次。通过 `RESEARCH_MONTHLY_SUPPLIER_SCOPE=all` 可显式切换为全部 `enabled=true` 供应商，不能由前端或单次请求临时扩大范围。两种模式都会把实际选定供应商快照写入批次，范围由部署配置控制，禁止随机截断或超出配置范围创建子任务。

### 2.3 手动研究、月报默认与周报预留边界

- 监控轨继续承担高频、确定性的日常风险监测。
- 本期默认周期能力为最多 100 家供应商月报；周报能力随同批次流程预留，但管理员开关默认关闭，不建设独立周报执行器。
- 以约 150 家供应商、博查每月 1000 次额度计算，每家每周最多 2 次搜索约需 `150 × 4.35 × 2 ≈ 1305` 次/月；即使每家每周只有 1 次，也约需 653 次/月，无法为手动研究、异常和额度核对保留足够余量。
- 既有日报保持历史兼容且不注册；周报只有在管理员调度开关开启、额度与资源预检通过且平台总开关 `RESEARCH_TRACK_ENABLED` 未关闭时才注册，任何情况下都不得创建空 `supplier_scope` 的全局定期研究任务。
- 月报覆盖上一个自然月的趋势、重复信号、风险变化与试点供应商横向概览，并可复用仍可回验的既有证据，避免无意义重复抓取。默认 100 家、每家最多 3 次搜索约需 300 次/月；切换全量 150 家后约需 450 次/月，必须先提高额度或接受无安全余量的运行风险。
- 周报覆盖上一个自然周的新风险、变化和待核实事项；开启周报不会关闭月报，二者共享全局额度、单 Worker队列和去重证据池。

## 3. 总体架构

```text
手动入口                         APScheduler
POST /research/tasks              每月月报 / 可选周报
      │                                  │
      │                         创建 research_batch
      │                         月报按范围快照供应商
      │                         分批创建 supplier task
      └──────────────┬───────────────────┘
                     ↓
            PostgreSQL research_tasks
             租约 / 取消 / 预算 / 幂等
                     ↓
              research-worker
                     ↓
          LangGraph Research Workflow
    ┌────────────────┼─────────────────────┐
    │                │                     │
监控轨证据       搜索与候选发现        受控读取策略
                                      HTTP → Crawl4AI
                                      登记 RSSHub 路由
    └────────────────┼─────────────────────┘
                     ↓
           证据分级、去重、交叉验证
                     ↓
           结论、引用与供应商报告草稿
                     ↓
       批次聚合器（不重新搜索或抓取）
                     ↓
       组合月报/周报 + 供应商执行明细
```

手动任务、月报子任务和开关启用后的周报子任务必须调用同一个 `build_research_graph()`。三者只允许在触发方式、时间窗口、供应商范围和预算配置上不同，不能维护多套研究逻辑。

## 4. LangGraph 受控研究图

### 4.1 图状态

`ResearchGraphState` 至少包含：

- `task_id`、`run_id`、`task_type`、`supplier_ids`、`period_start`、`period_end`；
- 任务配置快照和图版本；
- 已使用搜索次数、候选数、页面数、Token、金额、步骤数；
- 查询计划、候选引用 ID、已保存来源 ID、已回验引用 ID；
- 当前证据缺口、失败分类、下一动作；
- 取消、预算耗尽和停止原因。

图状态只保存引用标识和受限摘要，不复制完整网页正文、密钥、Cookie、模型隐藏思维链或任意浏览器配置。

### 4.2 节点与条件边

```text
initialize
  → load_supplier_context
  → load_monitoring_evidence
  → plan_queries
  → search_web
  → rank_candidates
  → read_candidate
       ├─ 静态正文成功 → register_evidence
       ├─ 空正文/需 JS → read_with_crawl4ai
       ├─ 登记 RSSHub → read_registered_feed
       ├─ 403/WAF/robots/认证 → block_source
       └─ 429 → cool_down_source
  → evaluate_evidence
       ├─ 证据不足且预算允许 → refine_queries → search_web
       ├─ 证据充分 → compose_report
       └─ 达到上限 → compose_insufficient_report
  → verify_claim_citations
       ├─ 回验失败 → remove_or_downgrade_claim
       └─ 回验通过 → persist_report
  → finish
```

### 4.3 Agent 可决策与不可决策范围

模型可以：

- 根据供应商名称、别名、行业、产品和原材料生成查询；
- 从平台返回的候选 ID 中选择优先读取项；
- 判断证据缺口并提出补充查询；
- 将证据组织为事实、推断和预测；
- 在证据不足时明确停止并降级结论。

模型不能：

- 直接传入任意 URL、代理、JavaScript、请求头或浏览器参数；
- 绕过 HTTPS、DNS、SSRF、重定向、robots、403、429、登录或付费墙限制；
- 修改预算、并发、域名冷却和工具白名单；
- 自行切换第二个付费搜索 Provider；
- 发布报告、改变 P1-P4、自动转为正式风险信号；
- 输出或保存隐藏思维链。

### 4.4 默认硬上限

以下数值作为开发默认值，正式启用前通过本地回放与费用测算校准：

| 限制 | 周报单供应商 | 月报单供应商 |
|---|---:|---:|
| Agent 最大步骤 | 10 | 12 |
| 基础搜索额度 | 1 | 2 |
| 证据不足时增强搜索 | 最多 1 | 最多 1 |
| 每轮候选上限 | 6 | 6 |
| 最大成功读取页面 | 4 | 5 |
| Crawl4AI 降级页面 | 1 | 2 |
| 报告模型调用 | 1 | 1 |
| Worker 初始并发 | 1 | 1 |

手动任务继续使用创建时预算快照；月报和可选周报分别使用管理员批准的预算模板。批次预算和单供应商预算必须同时满足，先达到任一上限即停止新增付费动作。

### 4.5 150 家供应商容量与额度测算

#### 博查 API

博查按每次已发出的搜索请求保守计量，不假设失败请求免费，也不以返回结果条数代替调用次数。

| 场景 | 月调用估算 | 判断 |
|---|---:|---|
| 周报，每家每周 1 次 | 约 653；5 周触发月为 750 | 挤压手动与异常额度，不采用 |
| 周报，每家每周最多 2 次 | 约 1305；5 周触发月为 1500 | 超过 1000，不采用 |
| 月报，每家基础 2 次 | 300 | 可行 |
| 月报，全部触发第 3 次 | 450 | 可行，但必须硬限额 |

每月 1000 次按以下方式预留：

- 全供应商月报硬上限 450 次，其中先为 `2 × 供应商数` 原子预留基础搜索额度；150 家为 300 次。
- 余下最多 150 次作为证据不足时的第 3 次搜索增强池，按任务实际需要申请，不平均提前消耗。
- 至少 300 次保留给管理员显式启动的手动研究。
- 至少 250 次作为失败请求、额度核对、紧急任务和供应商数量波动的安全余量。

月报创建前必须执行容量预检。如果当期启用供应商数量使 `2 × 供应商数 > 450`，或者 Provider 剩余额度不足以覆盖全部供应商基础额度，则整个批次不进入可执行状态并告警，禁止只运行前一部分供应商。

#### 周报开启资金门禁

周报开关不能只检查“当前剩余次数”，必须使用当月剩余周触发次数计算最坏上界：

```text
预计月需求 = 周报供应商数 × 当月周报触发次数 × 周报每供应商最大搜索数
           + 月报批次上限
           + 手动研究保留
           + 异常安全余量
```

按 150 家、一个包含 5 个周报触发点的月份、周报每家最多 2 次、月报 450 次、手动 300 次、安全余量 250 次计算，领导批准后的博查月额度至少需要 `150 × 5 × 2 + 450 + 300 + 250 = 2500` 次。实际开启时按当前供应商数量、当月触发次数和配置预算动态计算，不把 2500 写死为通用值。

管理员开启周报前必须同时满足：

1. 已记录领导批准的预算额度、批准人、批准时间和说明。
2. 博查控制台额度和平台 `monthly_limit` 已提高，且动态计算后的最坏上界不超过额度。
3. 月报、手动研究和安全余量不得因开启周报被挤占。
4. 150 家容量测试证明单 Worker能在下一周触发前完成一批，或者已有单独批准的扩容方案。
5. 当前无阻塞中的周期批次，Provider和Crawl4AI健康门禁通过，平台总开关 `RESEARCH_TRACK_ENABLED` 已开启。

任一条件不满足时，开启接口返回明确的预算或容量阻塞原因，不注册周报任务。关闭周报只阻止创建新批次；已经开始的批次由管理员选择完成或取消，不能静默丢弃。

#### 网页读取与 Crawl4AI

150 家供应商的理论上限为 750 个成功页面读取和 300 个 Crawl4AI 降级页面。静态 HTTPS 读取优先，只有空正文或明确需要 JavaScript 时才进入 Crawl4AI。单 Worker并发保持 1，批次允许在月初后持续排队执行，目标完成时间为 7 个自然日。

现有 Spike 曾观测到 Crawl4AI 单页约 6.61 秒，完整端到端样本也曾达到约 83.82 秒。按 300 个降级页面全部取较慢样本粗算，仅动态读取就可能占用约 7 小时，尚未包含搜索、静态读取、模型调用、冷却和失败超时。因此“月报额度可承受”不等于当前 2C4G 资源已经验收；必须继续保持浏览器并发 1，并以 7 日完成窗口做容量门禁。

正式启用前必须通过 150 个 Fake 任务和经批准的小样本真实读取测得：平均/95分位任务耗时、Crawl4AI内存峰值、整机可用内存和 7 日完成能力。未达到容量门禁时优先减少成功读取页数或延长批次窗口，不提高现有 2C4G 环境的浏览器并发。

#### 模型与存储

- 每个供应商的规划、证据评估和报告调用均计入任务及批次 Token 账本；模型价格未配置时不得把成本字段 `0` 解释为免费。
- 在真实全量运行前，用不少于 10 家不同资料量的供应商测量平均和 P95 Token，再计算 150 家上界并由管理员批准。
- 只持久化受限摘要、哈希、引用和结构化报告，继续执行保留期限；不得为了月报保存无限完整网页正文。

## 5. 定期研究批次设计

### 5.1 调度语义

- 月报默认：每月 1 日 `09:00`，覆盖上一个自然月，时区固定 `Asia/Shanghai`。
- 周报预留：每周一 `08:30`，覆盖上一个自然周；管理员开关默认关闭，只有第 4.5 节资金/容量门禁通过且平台研究轨总开关未关闭时才注册。
- Scheduler 只创建批次和子任务，不执行搜索、抓取或模型调用。
- 管理员必须显式启用调度、指定任务归属账号和批准周期预算；默认关闭。
- 同一周期同一类型只能存在一个批次；Scheduler 重启或重复触发不能重复计费。

### 5.2 供应商快照与任务扇出

1. Scheduler 创建周期批次并计算周期起止时间。
2. 在同一事务中快照所有 `enabled=true` 的供应商 ID、名称和版本时间。
3. 按固定小批量写入子任务，避免长事务；所有供应商仍必须最终入队，不设置静默数量截断。
4. 每个子任务的 `supplier_scope` 固定为单个供应商 ID。
5. 幂等键格式：`scheduled:{period_type}:{period_key}:supplier:{supplier_id}`。
6. 新增供应商从下一个周期进入；触发后被停用的供应商在执行前标记 `skipped`，不调用外部工具。
7. 子任务按照稳定顺序入队，并允许配置随机小抖动，避免所有外部请求集中在同一秒。

### 5.3 执行与失败隔离

- Worker 使用现有数据库租约逐个认领子任务；初期单实例、并发 1。
- 单个供应商失败只影响该子任务；其他供应商继续执行。
- 网络瞬态错误按既有规则有限重试；确定性的 403、WAF、robots、认证和校验错误不重试。
- Worker 重启后从 LangGraph checkpoint 恢复；付费工具调用以 `action_id` 做幂等保护。
- 新周期触发时若前一周期同类批次仍未完成，新批次先标记为容量阻塞并告警；周报与月报共享单 Worker时按已批准优先级串行执行，不允许并发争用同一额度。
- 批次完成状态允许 `succeeded`、`partial`、`failed`、`cancelled`、`budget_exhausted`；不得把部分失败伪装为成功。

### 5.4 月报与可选周报组合报告

月报或已启用周报的所有子任务到达终态后，由同一个批次聚合器创建一次组合报告：

- 汇总成功、失败、跳过、预算耗尽的供应商数量；
- 按 P1-P4、事实/推断/预测、行业和地区形成概览；
- 列出本周期风险上升、持续风险、风险缓解和证据不足的供应商；
- 每条组合结论必须继承子报告中的已回验引用；
- 聚合器不得重新搜索或抓取网页；默认只做确定性聚合，若调用一次模型润色，必须单独计入批次预算；
- 单个供应商报告仍可独立查看、重试和人工审核；
- 组合报告与子报告均固定“AI 生成，仅供内部参考，不作为重大决策依据”。

月报和周报可复用监控轨及既有研究中仍可回验且正文哈希未变化的证据。复用必须记录原任务、获取时间和哈希；过期、失效或不覆盖当前周期结论的证据必须重新研究。

## 6. 数据模型规划

### 6.1 新增 `research_batches`

建议字段：

- `id`、`period_type`（weekly/monthly）、`period_key`、`period_start`、`period_end`；
- `owner_user_id`、`status`、`supplier_snapshot`、`supplier_count`；
- `queued_count`、`running_count`、`succeeded_count`、`failed_count`、`skipped_count`、`budget_exhausted_count`；
- `budget_snapshot`、累计搜索/页面/Token/金额；
- `graph_version`、`created_at`、`started_at`、`finished_at`、`error`。

唯一约束：`UNIQUE(owner_user_id, period_type, period_key)`。

### 6.2 调整 `research_tasks`

- 增加可空 `batch_id` 外键；手动任务为空，定期子任务非空。
- `task_type` 增加 `monthly`；保留 `manual`、`daily`、`weekly` 兼容。
- 定期子任务必须满足 `supplier_scope` 恰好一个供应商 ID。
- 增加 `graph_version` 和 `checkpoint_thread_id`，用于执行版本追踪和恢复。
- 状态补充 `skipped`、`budget_exhausted`，使调度结果可准确表达。

### 6.3 新增 `research_tool_runs`

建议字段：

- `task_id`、`action_id`、`graph_node`、`tool_name`；
- 脱敏后的 `arguments_hash`、状态、尝试次数；
- `usage_snapshot`、`result_reference`、错误分类；
- `started_at`、`finished_at`。

唯一约束：`UNIQUE(task_id, action_id)`。它是付费动作的幂等账本，不由 LangGraph checkpoint 代替。

### 6.4 新增 `research_provider_quota_periods`

建议字段：

- `provider`、`period_key`、`monthly_limit`；
- `scheduled_reserved`、`manual_reserved`、`used`；
- `updated_at`。

唯一约束：`UNIQUE(provider, period_key)`。每次搜索前必须在数据库事务中原子预占额度，调用失败后仍按保守策略计入 `used`；只有能确认请求未离开本进程时才释放预占。单任务 `SearchBudget` 不能代替全局月度额度。

### 6.5 新增 `research_schedule_configs`

建议字段：

- `schedule_type`（weekly/monthly）、`enabled`、`cron_expression`、`topic_template`；
- `budget_template`、`approved_monthly_quota`；
- `approved_by_user_id`、`approved_at`、`approval_note`；
- `updated_by_user_id`、`updated_at`。

唯一约束：`UNIQUE(schedule_type)`。管理员的每次启停和预算变更写入现有审计日志。周报 `enabled=true` 不能绕过平台研究轨总开关和实时额度/容量预检。

### 6.6 调整报告关系

- `research_reports` 增加可空 `batch_id`；供应商报告绑定 `task_id`，组合报告绑定 `batch_id`。
- 使用数据库约束保证二者恰有一个非空。
- 组合报告引用只能指向批次子任务中已经回验的引用，不复制或伪造外部来源。

### 6.7 三类状态的唯一事实来源

| 状态 | 唯一事实来源 |
|---|---|
| 任务、批次、租约、预算、费用 | 现有业务表及新增批次/工具账本 |
| LangGraph 下一恢复节点 | LangGraph PostgreSQL Checkpointer |
| 前端执行图与审计回放 | `research_task_events` 及批次事件 |

Checkpoint 不作为审计记录、费用账本或报告事实来源。

## 10. 分阶段实施与验收

### 阶段 A：LangGraph 隔离 Spike

- 不接正式任务入口，不做真实付费调用。
- 使用 Fake Provider、MockTransport 和临时 PostgreSQL checkpoint。
- 验证条件分支、循环上限、取消、Worker 中断恢复和事件输出。
- 验收重点：恢复后不重复执行同一 `action_id` 的付费工具。

### 阶段 B：手动任务影子模式

- 正式任务仍由 legacy 执行器完成。
- LangGraph 只计算计划和下一动作，不执行真实搜索、抓取或模型调用。
- 比较两条路径的预算、事件和停止条件。

### 阶段 C：LangGraph 接管手动任务

- `RESEARCH_ORCHESTRATOR=langgraph` 只在本地开启。
- 接入监控证据、搜索、HTTP读取、Crawl4AI降级、证据评估、补充搜索和报告。
- 完成失败矩阵及引用回验后，才移除影子模式。

### 阶段 D：月报试点批次与全量切换

- 先用约 150 个 Fake 供应商验证：默认只选择 100 家、全量开关选择 150 家，以及额度预占、幂等、分批入队、单供应商失败隔离、暂停恢复和组合报告。
- 验证自然月周期、月报预算模板、既有证据复用、过期回验和月度组合报告。
- 经 1000 次月额度预检、Token 测算和管理员显式批准后，才允许一次小范围真实试运行；不得自动扩大到全部供应商真实调用。

### 阶段 E：周报能力预留与关闭态验收

- 复用月报批次、子任务、LangGraph和组合报告，不新增周报执行器。
- 实现管理员运行时开关、动态额度公式、批准记录和审计；周报开关默认关闭，并受现有研究轨总开关约束。
- 使用 Fake Provider验证 150 家、4周和5周月份的额度预检；博查额度仍为1000时必须拒绝开启。
- 本阶段不执行真实周报；只有领导批准增资、平台额度更新和容量门禁通过后，管理员才可手动开启。

### 阶段 F：前端与本地镜像

- 后端接口冻结后再实现批次 UI。
- 完成后端测试、前端测试、类型检查、生产构建和本地镜像健康验证。
- ECS 发布、旁路镜像风险和生产预算另行立项，不由本计划自动授权。

## 11. 必测场景

### 11.1 Agent 与工具策略

- 第一次搜索证据不足时生成第二组查询；达到搜索上限后停止。
- 静态页面成功时不调用 Crawl4AI。
- 空正文或明确需要 JS 时才允许 Crawl4AI 降级。
- 403、WAF、robots、认证和付费墙不得通过 Crawl4AI绕过。
- 429写入域名冷却，不立即重复访问。
- 搜索候选全部失败时允许使用监控证据生成“公开证据不足”报告。
- 引用回验失败时删除或降级对应结论。

### 11.2 调度与批次

- 同一月重复触发只创建一个批次和每供应商一个子任务。
- 周报默认不注册；研究轨总开关关闭时，单独开启周报管理员开关不能生效。
- 1000 次额度下开启周报被拒绝并返回预计需求；提高到满足最坏上界后才允许开启。
- 开启和关闭周报均有管理员、批准信息和审计记录。
- 默认最多 100 家按稳定 ID 顺序进入快照；`scope=all` 时全部启用供应商进入快照；两种模式均不得超范围静默扇出。
- 新增、停用、删除供应商的周期边界行为正确。
- 单个子任务失败不阻止其他供应商执行。
- 部分失败时批次为 `partial`，组合报告列出失败明细。
- 批次预算耗尽时未执行供应商具有明确终态和原因。
- Scheduler只创建任务，不执行外部调用。

### 11.3 恢复与费用

- Worker在搜索返回后、checkpoint前被终止，恢复后不重复搜索计费。
- Worker在模型返回后、报告提交前被终止，恢复后不重复模型计费或重复报告。
- 任务取消后不再启动新工具调用。
- 单任务用量、批次累计用量和Provider实际返回用量一致。

### 11.4 权限与审计

- 普通用户只能查看自己的手动任务；调度批次由指定管理员拥有。
- 只有具备 `research_schedule_manage` 权限的管理员可以启停调度或修改预算模板。
- 事件、工具账本和审计日志不包含 Key、Token、Cookie、完整提示词或隐藏思维链。

## 12. 完成定义

满足以下条件才可以宣称“受控研究 Agent 与全供应商定期研究已落地”：

1. 手动、月报和预留周报使用同一 LangGraph 版本和工具治理策略；周报默认关闭。
2. 月报默认覆盖最多 100 家稳定选定供应商；显式全量开关可覆盖全部启用供应商，无空范围全局任务和超范围静默扇出。
3. Agent 能在硬上限内完成补充查询、工具选择、证据评估和明确停止。
4. Worker中断后可恢复，且不重复产生已完成的付费工具调用。
5. 单供应商失败被隔离，批次能准确表达部分成功和预算耗尽。
6. 组合月报中的每条关键结论可追溯到子任务的已回验引用。
7. 默认 100 家供应商月报在最坏 300 次博查调用估算内运行；显式全量模式按最多 150 家、450 次上限预检，且全局额度预占不会侵占手动研究保留额度。
8. 周报开关默认关闭；只有领导批准信息、提高后的Provider额度、容量验收、研究轨总开关和管理员开关全部成立时才能注册。
9. 未经人工确认的研究结论不进入监控评分链或自动转为风险信号。
10. 所有测试使用 Fake/Mock 时不产生真实费用；任何真实试运行均需单独批准和预算记录。
11. 本地镜像验收完成不等同于 ECS上线；生产发布有独立的发布、回滚和容量验收记录。

## 13. 回滚方案

- 保留 `RESEARCH_ORCHESTRATOR=legacy`，可停止认领新 LangGraph 任务并恢复旧执行器。
- 数据库迁移采用加法变更，不删除现有任务、来源、引用、报告或事件字段。
- 已进入 LangGraph 的运行不得强行交给 legacy 续跑；应取消或由原图版本恢复，避免重复费用。
- 月报调度和周报管理员开关默认关闭；异常时先关闭对应注册，再让运行中工具调用安全结束或按任务取消。
- 回滚不删除批次、checkpoint和工具账本，保留审计与费用证据。

## 14. 当前明确不做

- 不重构监控轨、认证、供应商管理、风险评分或现有前端框架。
- 不引入 n8n、Celery、Kafka、图数据库或多 Agent 团队。
- 不开放任意代码执行、任意浏览器配置或任意 URL 工具。
- 不用多个付费搜索 Provider 自动互相降级。
- 不默认并行抓取全部供应商；先以单 Worker队列验证容量和费用。
- 不在现有1000次博查月额度下开启周报；预留能力不代表已批准真实周报调用。
- 不因为引入框架而宣称已经具备全网无边界抓取能力。

## 15. 实施记录

### 15.1 LangGraph 最小迁移图基线（2026-08-16）

- 已新增 `app/research/graph.py`，先建立最小受控图；当前补充搜索分支版本为 `research-graph-v2`。
- `RESEARCH_ORCHESTRATOR=legacy|langgraph` 已接入配置与研究 Worker；默认值仍为 `legacy`，因此现有任务不会因本次接入改变执行路径。`langgraph` 路径仅由任务显式启用，可随时切回 legacy。
- 图节点仍调用既有主题发现流程。它不自主规划查询、不自行选择工具、不增加真实网页、搜索或模型调用；任务、预算、引用、报告、租约与事件流仍以平台业务表为唯一事实来源。
- 隔离单测使用 `MemorySaver` 验证图的节点顺序和调用接口；`langgraph` 执行路径已使用 PostgreSQL checkpoint 保存同一任务线程的节点进度。checkpoint 不保存业务事实，也不替代工具账本、预算、租约、来源、报告或审计记录。
- 条件分支/循环、月报批次和周报开关仍按后续切片实施，不能据此宣称 Agent 已完整落地。
- 已通过独立图单测、legacy/langgraph 双路径研究轨回归，以及 Ruff、mypy 静态检查；回归使用 Fake Provider 和 Mock，不产生外部调用或费用。

### 15.2 工具调用幂等账本基线（2026-08-16）

- 已新增 `research_tool_runs` 和 `UNIQUE(task_id, action_id)`；动作 ID 仅由规范化参数的 SHA-256 哈希派生。账本只保存动作类型、参数哈希、状态、脱敏用量快照、结果主键引用和安全错误分类，不保存 URL、网页正文、完整提示词、Cookie 或密钥。
- 现有主题研究的公开搜索、候选页面读取和报告生成均在调用前认领账本。恢复时遇到既有 `running`、`failed` 或缺少可复用结果的 `succeeded` 记录会安全停止，而不会悄悄重放外部调用；已有来源或报告时复用其数据库主键引用。
- 当前账本解决“同一任务不得重复调用”这一费用安全底线；它不替代下一阶段的 PostgreSQL checkpoint，也不保证在外部响应返回但平台未持久化结果时自动继续。该不确定场景会停止任务并保留审计证据，待人工创建新任务或后续恢复机制处理。

### 15.3 PostgreSQL checkpoint 基线（2026-08-16）

- 引入官方 `langgraph-checkpoint-postgres==3.1.2`，与当前固定的 LangGraph 版本兼容。只在 `RESEARCH_ORCHESTRATOR=langgraph` 路径使用；legacy 不创建 checkpoint、不改变任务行为。
- checkpoint 线程键固定为 `research-task-{task_id}-{graph_version}`，状态只保留图版本、任务主键、节点进度和计数；图结构变更会使用新线程，避免旧图 checkpoint 被错误续跑；不放入 URL 正文、工具输出正文、模型提示词、密钥、Cookie 或数据库会话。
- 通过 Alembic `0036_langgraph_checkpoint_schema` 在应用/Worker 启动前预创建 checkpoint 表和普通索引，并写入官方迁移版本；运行时 `setup()` 只做幂等版本确认，避免在业务事务中执行 `CREATE INDEX CONCURRENTLY` 造成锁等待。
- PostgreSQL checkpoint 只提供“图已运行到哪个受控节点”的恢复信息，不能覆盖 `research_tasks` 租约、`research_tool_runs` 幂等账本、预算、来源、引用、报告或审计记录。恢复前仍以账本决定是否允许发起工具调用。
- 对“外部调用已发出但平台未保存可复用结果”的不确定状态，系统继续安全停止；checkpoint 不得被用于猜测性重放。已在隔离 PostgreSQL 验证 checkpoint 读取及同任务线程的节点恢复，再进入条件分支与循环开发。

### 15.4 证据不足时的一次确定性补充搜索（当前后端切片）

- 仅 `RESEARCH_ORCHESTRATOR=langgraph` 路径启用；legacy 继续保持一次主题搜索后的既有行为，作为随时可回退的基线。
- 初次搜索及受控读取结束后，平台统计已回验且有摘要的引用。固定阈值为至少 `1` 条：达到阈值即生成普通报告；低于阈值时，只有任务仍有 `max_queries` 余额且尚未补充过，才最多执行一次补充搜索。
- 补充查询不由模型生成，固定为“`{主题} 风险 公告`”。该查询、候选读取和报告生成仍通过既有预算闸门、HTTPS 页面读取器、`research_tool_runs` 和 PostgreSQL checkpoint 执行；补充搜索的查询不同，因此天然拥有独立动作 ID。
- 补充后仍无可用证据、或搜索次数预算已耗尽时，系统生成不调用模型的“公开证据不足”草稿并明确停止，不继续循环、不切换 Provider、不伪造结论，也不写入监控风险信号。
- 图的固定路径为：`monitoring_context → primary_discovery → evaluate_evidence → [supplemental_discovery → evaluate_evidence] → compose_report`。条件由平台确定性规则决定；模型没有查询规划、工具选择或预算控制权限。
- 图结构升级为 `research-graph-v2`，checkpoint 线程同时包含图版本，旧 `v1` 线程不会被新图错误续跑。
- 已在隔离 PostgreSQL 以 Fake/Mock 验证：首轮证据充分时不补充；首轮为空时只补充一次；两轮为空或搜索额度耗尽时生成不足草稿；checkpoint 在补充节点后恢复时不重复节点。全程不访问真实搜索、抓取或模型服务。

### 16.4 真实任务实体约束、心跳与报告可观测性修复（2026-08-18）

本地真实任务暴露出四项必须在 M1/M3 关闭前修复的问题：

1. Worker 心跳原先与主轮询循环共用线程；单次网页或远端模型调用超过 `60` 秒时，任务仍在执行但状态接口会短暂返回 `stale`。心跳必须使用独立数据库会话定期续期，直到当前任务结束或 Worker 收到停止信号。
2. 跨区气象信号虽然没有进入证据池，但后端仍为每条过滤结果写入执行图事件。后续只保留监控上下文汇总计数，不为跨区信号创建节点；前端同时忽略历史 `monitoring_signal_filtered` 事件。
3. 单供应商任务不得直接以用户输入的短简称作为唯一搜索实体。平台在调用博查/Tavily前必须把供应商法定全称加入实际查询词，并使用法定全称、去公司后缀核心名称、已登记别名或统一社会信用代码筛除实体不匹配候选；不满足实体闸门的候选不得读取、不得进入证据池、不得交给报告模型。
4. 搜索节点必须展示实际发送给 Provider 的查询词、Provider、原始候选数和实体过滤数。报告节点必须展示实际 Provider、模型版本和 Token 用量；报告生成或平台引用校验失败时，`research_tool_runs` 与执行事件都必须落为失败，不能遗留 `running`。

远端模型能力边界保持明确：当前 LangGraph 的证据评估仍是平台确定性规则，远端 LLM 只在 `compose_report` 阶段接收最多 20 条已回验证据并生成结构化事实、推断和预测，不执行无限自主检索，也不替代供应商实体校验、地点校验、引用回验或人工确认。

### 16.1 M1 本地启动约定（2026-08-17）

- `app` 和 `scheduler` 只负责 API、数据库迁移及创建 `queued` 任务，不会替代 `research-worker` 认领任务；没有 Worker 时，任务显示等待 Worker 是正确的可观测状态。
- 本地手动研究推荐使用 `scripts/start-research-worker.ps1`，它仅在当前 Compose 子进程中设置 `RESEARCH_WORKER_ENABLED=true`、`RESEARCH_WORKER_MODE=topic_source_discovery` 和 `RESEARCH_ORCHESTRATOR=langgraph`，然后启动 `research-local-test` profile。已准备旁路 Token 且需要动态页面回退时，显式增加 `-EnableCrawl4AI`；默认不启动浏览器回退。
- 研究轨全局配置默认仍保留 `legacy`，作为回滚安全边界；脚本显式覆盖后才进入 LangGraph 路径。`local_lifecycle_test` 仍可用于完全不访问外部 Provider 的生命周期验证。
- `SEARCH_PROVIDER=none` 时不会发起外部搜索；启用真实 Provider、网页读取或模型调用仍需逐次授权、预算记录和独立验收。本地启动脚本不读取、打印或改写任何密钥。
- M1 本轮只验收启动约定和本地 Worker 闭环，不改变 ECS 状态、不注册自动月报/周报、不启动 Scheduler 常驻，不把固定图误称为具备全网无边界抓取能力。

### 16.2 M1 Worker 心跳与等待状态诊断（2026-08-17）

- `research-worker` 启动时注册心跳，按配置间隔续期，收到停止信号后写入 `stopped`；进程异常退出时保留最后心跳，由读取接口按阈值返回 `stale`，不把失联 Worker 自动当作可恢复执行器。
- 新增 `GET /api/v1/research/worker/status`，沿用研究任务权限隔离，返回总体 `online/stale/offline`、Worker 模式/编排器和脱敏时间信息。该接口只用于本地运维诊断，不授予启动 Worker 或执行任务的权限。
- `RESEARCH_WORKER_HEARTBEAT_INTERVAL_SECONDS` 默认 15 秒，`RESEARCH_WORKER_HEARTBEAT_STALE_SECONDS` 默认 60 秒；参数只影响诊断，不改变任务租约、预算、工具幂等或外部调用门禁。
- 本切片使用 Fake/Mock 完成心跳生命周期、无 Worker、过期 Worker 和既有 Runner/Worker 回归；不启动真实 Provider、网页读取、模型或 ECS。
