## 3. 产品定位与不可突破的边界

系统采用“双轨”结构：

1. **监控轨**：高频、确定性地处理天气、自然灾害、官方风险信号，形成风险事件、供应商关联和 P1～P4 提醒。
2. **研究轨**：围绕供应商、行业、政策、原材料等主题开展受控公开信息研究，形成带引用的内部研究草稿。

研究轨必须遵守：

- 只有用户明确点击“开始任务/开始研究”后，手动任务才可搜索、读取网页或调用模型。
- 研究报告固定为 `draft / pending`，仅供参考。
- 研究结论不得自动写入 `raw_signals`、风险评分或 P1～P4 提醒。
- 只有显式人工“结论转正”后，结论才可进入监控链；该能力当前仍不是本次验收重点。
- LangGraph 只负责受控编排，不替代数据库中的任务、租约、预算、工具账本、事件、来源和报告事实。
- 已彻底移除引入 PydanticAI 的计划，不要重新加入。
- 搜索和模型调用必须受任务预算、Provider 月度额度、幂等账本和租约控制。

## 4. 当前研究轨架构

手动研究任务的主要流程：

```text
用户创建任务
  → 用户点击开始任务
  → Worker 领取任务租约
  → 载入供应商范围内的监控轨证据快照
  → 生成单供应商实体约束查询
  → 博查/Tavily 搜索公开候选
  → 供应商实体相关性过滤
  → 公共 HTTPS/DNS/重定向安全检查
  → 原生网页读取，必要时回退 Crawl4AI
  → 保存 ResearchSource 与已回验 ResearchCitation
  → LangGraph 确定性评估证据
  → 证据不足时最多执行一次补充搜索
  → 远端 LLM 生成结构化研究草稿
  → 平台校验并替换为真实回验引用
  → 保存 draft/pending 报告
```

LangGraph 当前图：

```text
monitoring_context
  → primary_discovery
  → evaluate_evidence
  → [supplemental_discovery → evaluate_evidence]
  → compose_report
```

关键事实来源：

- `research_tasks`：任务、租约、预算和终态。
- `research_task_events`：前端动态执行图的追加式事件流。
- `research_tool_runs`：搜索、页面读取、报告调用的幂等和恢复账本。
- `research_sources` / `research_citations`：真实读取证据及回验引用。
- `research_reports`：结构化报告草稿。
- LangGraph PostgreSQL checkpoint：仅保存编排进度，不能替代上述业务表。

## 5. 已完成的主要功能

### 5.1 受控研究 Agent

- 已引入 LangGraph 与 PostgreSQL checkpointer。
- 支持 `legacy | langgraph` 可逆编排开关。
- 支持首轮搜索、确定性证据评估、最多一次补充搜索、报告生成。
- 搜索、页面读取和报告调用均有幂等工具账本。
- 支持任务租约续期、取消、恢复和遗留工具调用对账。
- 未知外部调用状态会安全停止，不猜测性重复调用，避免重复计费。

### 5.2 监控轨信号融合

- 研究任务开始时按供应商范围载入当前有效监控轨证据。
- 仅接收已有成功 AI 分析且无需人工复核的信号。
- 监控轨来源与公网来源分开标识、去重和展示。
- 区级行政区不匹配的气象信号在进入研究证据池前直接过滤。

### 5.3 公开信息采集

- 搜索 Provider：博查为当前主要配置，代码同时保留 Tavily 适配能力。
- 页面读取顺序：受控直接读取；需要浏览器渲染时回退 Crawl4AI。
- RSSHub 仍作为特定 RSS/Atom 路由旁路，不是通用搜索 Agent。
- 所有来源必须经过 HTTPS、DNS、重定向和私网地址防护。
- 候选读取失败会记录脱敏 `error_kind`/HTTP 状态，不记录密钥或正文。

### 5.4 动态研究执行图

- 前端按追加式 `ResearchTaskEvent` 增量轮询并动态生成节点。
- 公网候选节点纵向自然排列，不使用固定高度画布或内部纵向滚动条。
- 过滤掉的跨区气象信号不生成新节点；历史 `monitoring_signal_filtered` 事件也被前端隐藏。
- 搜索节点展示实际查询词、Provider、原始候选数、实体通过数和过滤数。
- 报告节点展示 Provider、模型、输入 Token 和输出 Token。

### 5.5 周期研究规划

- 月报按与手动任务相同的研究调度流程，对供应商逐一扇出任务。
- 当前方案只考虑最多 100 家供应商，不新增“核心供应商”字段。
- 若未来预算获批，再导入并执行全部约 150 家供应商。
- 月报默认关闭，必须通过配置显式开启。
- 周报仅保留运行时开关和额度预检，默认关闭；博查每月 1000 次额度下不得默认启用。
- 周报开启必须经过管理层批准增加预算。

## 6. 2026-08-18 四项问题与修复状态

### 6.1 Worker 短暂心跳过期

根因：心跳原来只在主轮询线程更新；远端报告调用约 88 秒，超过 60 秒过期阈值。

已修复：

- Worker 启动独立后台心跳线程。
- 心跳线程使用独立数据库 Session。
- Crawl4AI 或远端 LLM 阻塞主执行线程时仍持续续期。
- Worker 真正停止时仍写入 `stopped`，失联时仍按阈值进入 `stale/offline`。

### 6.2 跨区气象信号仍出现在执行图

根因：后端虽未保存跨区证据，仍为每条过滤结果创建 `monitoring_signal_filtered` 事件，前端又把它画成节点。

已修复：

- 后端只累计 `filtered_location_count`，不创建逐条过滤事件。
- 前端隐藏历史 `monitoring_signal_filtered` 事件。
- 地点匹配继续要求国家、省/州、市、区县精确一致，不允许同城跨区模糊命中。

### 6.3 “上海华美”搜索成“盛美上海”

只读核查证明，任务原来发送给博查的查询词确实是用户主题，名称错误来自搜索结果歧义，不是平台主动改写。

已修复：

- 单供应商任务自动把供应商法定全称加入实际查询词。
- 使用法定全称、去公司后缀核心名、已登记别名、统一社会信用代码过滤候选。
- 额外允许“用户主题中真实出现、且与法定名称开头一致的至少 4 字简称”。
- “上海华美”可以通过，“盛美上海”会被过滤。
- 实体不匹配候选不读取、不生成来源节点、不进入证据池、不交给报告模型。

对当前验收任务，预期实际查询词为：

```text
"上海华美电梯装饰有限公司" 查询上海华美最近30天的风险情况
```

### 6.4 报告为空、远端 LLM 是否执行

任务 `2158` 的历史证据：

- 实际调用模型：`qwen3.6-plus`。
- 输入 Token：2555。
- 输出 Token：5133。
- 调用耗时约 88 秒。

当前能力边界：

- 远端 LLM 只在 `compose_report` 阶段生成一次结构化报告。
- 每条信号并没有单独交给远端 LLM 分析；证据评估仍是平台确定性逻辑。
- 模型返回后还必须通过报告结构和引用校验，校验失败不会保存报告。

已修复：

- 报告成功事件展示真实 Provider、模型与 Token。
- 模型已返回但报告校验失败时，工具账本会结束为 `failed`。
- 已消耗 Token 会被记录，不再因平台校验失败而漏记。
- 历史任务 `2159` 遗留工具账本 `834` 已通过现有 `reconcile_stale_tool_runs` 服务从 `running` 收口为 `failed / stale_reconciled`。

## 10. 尚未关闭的问题

### 10.1 真实公网采集能力仍需用户任务验证

单元测试和旁路健康只能证明编排与接口正确，不能证明本次真实站点一定可读。下一轮必须以用户手动任务的实际候选逐条分类：
