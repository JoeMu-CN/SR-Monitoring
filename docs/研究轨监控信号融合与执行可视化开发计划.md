# 研究轨监控信号融合与执行可视化开发计划

> 状态：2026-08-15 后端与前端均已实现并完成本地构建、测试和 app 健康验收；登录后实景视觉验收待具备有效用户会话时补充。

## 1. 目标与问题

本次开发解决两个已确认问题：

1. 手动研究任务目前只展示会被覆盖的 `current_step`，无法回放搜索、读取、筛选、引用和报告生成过程。
2. 研究报告目前只使用本任务从公网搜索并读取的来源，没有复用监控轨已经采集、分析和关联到供应商的风险信号。

目标是在不改变监控轨评分链、不自动转正研究结论、不增加第二套调度系统的前提下，形成：

```text
供应商范围 -> 监控轨证据快照 ─┐
                               ├-> 研究证据池 -> 报告草稿
研究主题 -> 公网搜索与受控读取 ─┘

研究执行步骤 -> 只追加事件流 -> 前端增量轮询 -> 动态有向网络图
```

## 2. 方案取舍

### 2.1 监控轨上下文

采用复用方案，不新增独立上下文表：

- 将符合条件的监控信号复制为当前任务的 `research_sources` 快照，`source_type` 固定为 `monitoring_signal`。
- 使用原始风险信号的公开 HTTPS URL、标题和正文摘录生成 `research_citations`，继续走现有引用回验和报告输入逻辑。
- `metadata` 只记录追溯所需的 `alert_id`、`event_id`、`signal_id`、`supplier_id`、风险等级、评分和数据源代码，不保存凭据或内部备注。
- 研究报告输入同时包含监控轨快照和本次公网搜索来源，二者在来源类型上明确区分。

不直接把全部 `raw_signals` 发送给模型。仅纳入同时满足以下条件的信号：

- 关联到任务显式选择的 `supplier_scope`；
- 对应提醒仍为 `current`；
- 已有成功的 AI 分析记录；
- 最新成功分析记录 `needs_review=false`；
- 原始来源为无凭据的公开 HTTPS URL；
- 每个任务最多 5 条，按 P1 至 P4、提醒更新时间倒序选择。

若任务未指定 `supplier_scope`，跳过监控轨上下文，不回退到读取全库信号。前端供应商选择器会明确展示这一安全边界。

### 2.2 执行事件流

新增 `research_task_events` 只追加表，核心字段：

- `task_id`：所属研究任务；
- `event_type`：稳定机器事件类型；
- `node_key` / `parent_node_key`：前端组装节点和边；
- `status`：`pending`、`running`、`succeeded`、`failed`、`skipped`、`info`；
- `label`：可展示的中文短文本；
- `detail`：脱敏 JSON，只放计数、序号和内部记录 ID；
- `occurred_at`：事件时间。

事件接口：

```http
GET /api/v1/research/tasks/{task_id}/events?after_id=0&limit=200
```

- 按事件 ID 正序返回；
- `after_id` 用作增量游标；
- 任务创建者只能读取自己的任务，`risk_admin` / `platform_admin` 沿用现有管理范围；
- 不返回 Worker 标识、搜索 Key、模型请求体、完整网页正文或异常原文。

前端第一版继续轮询，不引入 WebSocket/SSE。事件量和刷新延迟证明轮询不足后再评估升级。

## 3. 真实事件节点

后端只记录已经实际发生的动作，不为尚未实现的“自主推理”制造动画：

| 阶段 | 主要事件 |
|---|---|
| 任务治理 | `task_created`、`execution_requested`、`worker_claimed`、`task_succeeded`、`task_failed`、`task_cancelled` |
| 监控上下文 | `monitoring_context_started`、`monitoring_signal_added`、`monitoring_context_completed`、`monitoring_context_skipped` |
| 公网检索 | `web_search_started`、`web_search_completed` |
| 候选读取 | `source_read_started`、`source_added`、`source_read_failed`、`source_duplicate_skipped` |
| 报告生成 | `report_generation_started`、`report_generated` |

来源分级和交叉验证只有在后端真正落地对应规则与结果后，才能增加相应节点。

## 4. 后端开发任务

### B1. 数据模型与迁移

- 增加 `research_task_events`、外键、状态约束和 `(task_id, id)` 索引。
- ORM 增加任务到事件的一对多关系，任务删除时级联删除事件。
- 保持 Alembic 单一 head，升级和降级均可执行。

### B2. 事件服务与 API

- 提供追加事件和按游标查询事件的最小服务函数。
- 创建、开始、认领、结束以及研究执行器关键步骤写入事件。
- 复用现有任务所有权校验，不扩大权限。

### B3. 监控轨证据融合

- 按 `supplier_scope` 查询当前提醒、风险事件、关联原始信号、数据源和最新成功 AI 分析记录。
- 把最多 5 条合格信号保存为研究来源/引用快照。
- 公网搜索候选先按任务内 URL 去重，读取后再按正文哈希去重。
- 报告输入继续使用现有最多 20 条已回验引用，不新增模型调用轮次。

### B4. 测试与验证

- 监控信号满足条件时进入研究证据；待复核、非 HTTPS、过期提醒、非任务供应商不得进入。
- 相同 URL 或正文哈希的公网候选被跳过且留下 `skipped` 事件。
- 事件接口覆盖增量游标、顺序、任务所有权和管理员读取。
- 运行研究轨定向测试、Ruff、mypy、Alembic 单 head 与 `git diff --check`。
- 测试全部使用本地数据库夹具和 Fake Provider，不调用搜索、网页、模型或付费 API。

## 5. 前端实施范围

负责人确认效果图后，按当前 macOS 风格配色和深色页面体系完成前端实现：

- 左侧任务列表与任务创建区；
- 中央分层有向网络图；
- 监控轨来源与公网来源使用不同颜色；
- 节点显示等待、执行中、成功、失败、跳过状态；
- 右侧或底部显示当前步骤、来源详情、预算和耗时；
- 动效只表达后端事件状态，不模拟不可观测的模型思维过程。

实现复用现有 React、Tailwind、Motion 与 Lucide，不新增图形库：

- 创建任务时可搜索并多选供应商，创建载荷写入 `supplier_scope`；
- 使用事件 ID 游标每 2.5 秒增量获取运行中任务事件，并同步刷新任务与来源；
- 桌面端以 DOM 节点实际位置计算 SVG 贝塞尔连线，显示任务、监控轨、公网检索、证据池和报告节点；
- 窄屏降级为同一真实事件的时间线，避免横向网络图影响可读性；
- 支持键盘焦点、节点详情、原始来源跳转和 `prefers-reduced-motion` 动画降级；
- 动效只表达后端已记录事件，不生成或暴露模型思维链。

## 6. 明确不在本轮实施

- WebSocket、SSE、Kafka、Redis Stream 或通用事件总线；
- 图数据库、知识图谱或自动处置工作流；
- 自动从研究主题猜测供应商并读取全库信号；
- 将待复核信号作为已确认事实；
- 自动把研究结论写入 `raw_signals` 或改变 P1-P4；
- 新增模型调用轮次、自动启动 Scheduler/Worker 或真实外部请求；

## 7. 完成定义

本功能完成必须同时满足：

1. 指定供应商的研究任务能在报告证据中同时看到合格监控信号和新搜索来源。
2. 执行过程能通过事件接口按游标增量回放，失败和跳过原因不泄露敏感信息。
3. 无供应商范围时不读取全库监控信号。
4. 现有监控轨采集、分析、匹配、评分和人工转正边界保持不变。
5. 定向测试、静态检查和迁移检查通过，且验证过程中无真实外部调用。
6. 桌面端可按真实事件展示动态网络图，窄屏可用时间线查看相同事件，且不新增前端图形依赖。

## 11. 真实任务可视化与实体相关性修复（2026-08-18）

- 执行图只展示进入研究流程的监控信号；区级行政区不匹配的气象信号在监控上下文装载时直接过滤，只保留汇总计数，不生成逐条节点。前端对历史 `monitoring_signal_filtered` 事件也不再绘制。
- 公网搜索节点展示实际发送给 Provider 的查询词和 Provider 名称，而不是只显示“公开来源搜索完成”。单供应商任务使用供应商法定全称约束搜索，并在页面读取前执行确定性实体相关性过滤。
- 实体不匹配候选不产生来源读取节点、不进入证据池，也不参与报告；搜索节点只显示原始候选数、通过实体闸门数量和过滤数量的汇总。
- 报告生成节点展示远端 Provider、模型和输入/输出 Token。报告草稿继续只呈现经过平台引用回验的结构化结论；模型输出校验失败时节点显示失败，工具账本不得遗留为运行中。
- Worker 心跳改为独立续期，远端 LLM或 Crawl4AI 长调用期间不再短暂显示“心跳过期”；真正停止或失联仍按原阈值进入 `stale/offline`。
- 供应商简称消歧补充最小规则：仅把用户主题中实际出现、且与法定名称开头一致的至少 4 字片段作为实体词；本例允许“上海华美”通过，同时继续拒绝“盛美上海”。
- 本地验证：镜像内 research 相关 `126` 项回归全部通过，关键文件 Ruff/mypy 通过；前端 `6/6` 单测、TypeScript 和 Vite 构建通过。历史任务 `2159` 的遗留报告账本 `834` 已通过现有恢复服务由 `running` 收口为 `failed`。
- 已重建并替换本机 `app` 与 `research-worker`；两者运行同一新镜像，App 健康接口返回 `status=ok / database=ok`，Worker 心跳为 `online / topic_source_discovery / langgraph`，Crawl4AI 保持 healthy。localhost 登录页加载正常且无前端控制台错误；登录后的人工研究任务仍由用户手动验收，避免开发验证额外消耗搜索和模型额度。
